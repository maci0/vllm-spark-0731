# 07-5. 세 대와 네 대

이 페이지는 07-4. 세 대·네 대·여덟 대의 상세 내용입니다.

세 대가 항상 두 대보다 좋은 것은 아니다. TP degree가 model과 runtime의 분할 방식에 맞지 않으면 통신 비용이 계산 이득을 먹는다.

## 세 대

세 대에서는 TP=3을 기본값으로 가정하지 않는다. DP 또는 PP를 검토하고, 실제 통신 패턴을 측정한다. 모델이 메모리에 들어가는 것과 end-to-end latency가 개선되는 것은 별도다.

## 네 대

네 대는 일부 model parallel recipe에서 깔끔한 분할점이 될 수 있다. 그래도 NVLink가 없는 DGX Spark 환경에서는 스위치, RoCE, NCCL topology가 결과를 좌우한다.

## 판단표

| 질문 | 세 대 | 네 대 |
|---|---|---|
| 큰 모델 수용 | 가능성 확인 | 분할 선택 폭 증가 |
| 통신 복잡도 | 높음 | 더 높음 |
| 권장 첫 검증 | DP·PP 비교 | TP=4와 DP 비교 |

노드 수보다 workload와 topology를 먼저 고정한다.
