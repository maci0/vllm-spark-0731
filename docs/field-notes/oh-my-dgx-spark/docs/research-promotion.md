# 리서치 로그에서 책 본문으로 승격하는 규칙

리서치 자동화의 목적은 수집한 내용을 곧바로 책에 확정하는 데 있지 않습니다. 먼저 날짜별 상세 분석 문서를 `docs/`에 보관하고, 출처와 실험 조건을 확인한 뒤 안정적인 본문으로 승격합니다. WikiDocs의 날짜별 공개 페이지는 배포할 때 이 원문에서 생성되는 표현물입니다.

## 상태

| 상태 | 의미 | 다음 단계 |
|---|---|---|
| `candidate` | URL만 수집된 후보 | 원문 확인 |
| `analyzed` | 출처를 읽고 요약·분류함 | 조건과 충돌 확인 |
| `corroborated` | 독립 출처 또는 공식 자료가 같은 사실을 지지함 | 재현 설계 |
| `reproduced` | 조건을 고정한 실험을 통과함 | 본문 PR 검토 |
| `promoted` | 별도 본문 PR이 검토·병합됨 | 기준일과 버전 유지 |
| `stale` | 버전·상태가 바뀌어 다시 확인해야 함 | 최신 자료 재수집 |

## 승격 게이트

본문으로 옮기기 전에 다음 항목을 확인합니다.

- 원문 URL과 출처 유형이 있습니다.
- 모델 revision, quant, runtime/commit, 노드 수, context, KV dtype, 동시성, 측정 방법이 기록되어 있습니다.
- 관찰된 증상과 원인에 대한 해석이 분리되어 있습니다.
- 수치가 공식 자료인지, 직접 측정인지, 단일 커뮤니티 보고인지 구분되어 있습니다.
- 재현하지 못한 항목은 본문에서 확정형으로 쓰지 않습니다.
- 장애·OOM·전력 관련 내용은 실패 조건과 복구 방법을 함께 확인합니다.
- 본문 PR은 한 주제 또는 한 장의 변경으로 작게 만듭니다.

## 자동화 경계

자동 리서치 Workflow는 다음 산출물까지만 만듭니다.

1. 수집 Issue
2. `docs/research-issue-N_YYYY-MM-DD.md` 날짜별 상세 분석
3. 위 내용을 검토하기 위한 draft PR

`Publish WikiDocs`가 `docs/`의 날짜별 보고서를 부록 B 아래의 `appendix-b-research-issue-N_YYYY-MM-DD.md` 공개 서브챕터로 변환합니다. 따라서 `book/appendix-b-research-issue-N_YYYY-MM-DD.md`와 랜딩 페이지에 daily 내용을 자동 PR로 함께 커밋하지 않습니다.

예약 리서치 자동화는 날짜별 로그 외의 안정된 `book/` 본문을 수정하지 않습니다. 승격 조건을 충족한 보고서는 사람이 `Draft a Reviewed Book Chapter` Workflow에 보고서 한 편과 책 파일 한 편을 지정해 Terra 초안을 만들 수 있습니다. 이 Workflow는 지정한 기존 장 하나만 수정하며, 자동 병합하지 않고 draft PR에서 멈춥니다. DeepSeek, Qwen, MiniMax, 네트워크와 장애 대응 내용은 사람이 근거와 diff를 확인한 뒤에만 본문이 됩니다.

Sol 검토는 자동 단계에 넣지 않습니다. 서로 충돌하는 근거, 장 전체의 재구성, 구매 판단에 직접 영향을 주는 수치처럼 잘못 쓰였을 때 비용이 큰 부분에만 사람이 따로 요청합니다.

## 기록 보존

승격한 뒤에도 원래 Issue, 분석 문서, 실험 로그와 기준일을 삭제하지 않습니다. 나중에 모델·런타임·펌웨어가 바뀌었을 때 어떤 근거로 본문을 작성했는지 추적할 수 있어야 합니다.
